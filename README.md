# pydata-helsinki.github.io

Source for the [PyData Helsinki](https://pydata-helsinki.github.io/) site.

The site is generated by `build.py`, a small custom builder (no framework):
one YAML file per event in `events/` renders into

- the index page (upcoming/past listings; old `#YYYY-MM-DD` anchors preserved)
- a page per event at `/events/<slug>/` with [schema.org Event](https://schema.org/Event)
  JSON-LD, so events appear in Google's event search results
- `events.ics` — subscribable iCalendar feed
- `feed.xml` (Atom) and `events.json` (JSON Feed)
- `sitemap.xml`

Everything listed in `STATIC` in `build.py` (assets, slides, for-speakers,
for-companies, style.css) is copied through unchanged.

## Adding an event

Copy the most recent file in `events/`, rename it `YYYY-MM-DD-venue.yaml`
(the filename becomes the URL slug), and edit. Minimal example:

```yaml
title: Meetup at Acme
start: 2026-09-15 17:30
end: 2026-09-15 20:30
venue:
  name: Acme
  address: Katukatu 1        # street address helps event SEO, add when known
registration:
  url: https://www.meetup.com/pydatahelsinki/events/123456789/
  platform: Meetup           # or Luma, pretix, ...
talks:                       # optional, add as the programme firms up
  - speaker: Ada Lovelace
    speaker_url: https://example.com
    title: Notes on the Analytical Engine
    lightning: true          # optional
    video: https://youtu.be/…  # optional, add after the recording is up
```

Commit to `main` and GitHub Actions builds and deploys. A daily scheduled
build moves events from "upcoming" to "past" without needing a commit.

## Building locally

```
uv run build.py            # output in _site/
python3 -m http.server -d _site
```

(`build.py` declares its dependencies in the inline script metadata, so
`uv run` handles them; alternatively `pip install jinja2 pyyaml icalendar`.)
